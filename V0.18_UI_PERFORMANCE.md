# v0.18 — UI and performance pass

## Hot path

Największym kosztem v0.17 przy `CH+/CH-` był pełny powrót/reload `/channels` przed kolejną aktywacją kafelka. Zapisane snapshoty Orange potwierdzają, że `Channel-ChannelWrapper` pozostaje w DOM także przy expanded playerze.

v0.18 wykorzystuje ten fakt:

1. przywraca kontrolki Orange,
2. natywnie klika `IconPlayerExpandedToMini`,
3. czeka na background player,
4. aktywuje kolejny istniejący kafelek,
5. zachowuje sprawdzoną ścieżkę hover → prawdziwy Play button → native tap,
6. rozszerza nowy player i odsłania obraz dopiero po potwierdzonej klatce.

Fallback do `loadUrl(/channels)` pozostaje tylko wtedy, gdy lista kanałów faktycznie zniknęła z DOM.

## Mniej narzutu

- bridge JS jest primowany raz per dokument; kolejne poll-e wykonują tylko małe wyrażenie,
- pełny EME matrix jest lazy po realnym stall-u,
- stabilizacja po prawdziwej klatce: 120 ms zamiast 650 ms,
- poll-e przełączania skrócone do około 60–120 ms,
- discovery kończy się po dwóch zgodnych snapshotach zamiast czekać minimum 1,8 s.

## UI

Lista kanałów pokazuje numer, logo, nazwę i aktualny `Channel-ProgramName`. Pierwsze widoczne logo są pobierane w tle; dalsze dopiero po fokusie, żeby obrazki nie konkurowały z tuningiem.

Podczas przełączania UI pokazuje neutralne szare tło, spinner i `Ładowanie…`. Szczegóły techniczne trafiają tylko do diagnostyki.

## Login

Na czystej instalacji brak cookies Orange oznacza, że probe `/channels` może tylko doprowadzić do logowania. v0.18 pomija ten round-trip i od razu preładuje `/landing_page` w ukrytym WebView. Dla istniejących cookies normalny session probe pozostaje.
