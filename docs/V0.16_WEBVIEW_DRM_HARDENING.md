# v0.16 — WebView / DRM compatibility hardening

## Observed failure

On the DIW377 the app reached Orange's expanded player but remained at:

- `readyState = 0`
- decoded size `0x0`
- no render signal

The same Orange account/channel flow renders normally in a full browser. Therefore v0.16 treats the host WebView environment, media initialization timing, UA compatibility, protected-media permission and Android compositor state as independent failure domains.

## Safeguards

### 1. Do not disturb MSE/EME attachment
`playerAction()` no longer calls `video.play()` while `readyState == 0` or Orange has not attached a usable media source. It waits for Orange's own MSE/EME pipeline first.

### 2. Capability probe
The bridge records:
- secure context
- `navigator.requestMediaKeySystemAccess`
- `MediaSource`
- H.264/AAC MSE support
- Widevine `com.widevine.alpha` key-system access
- `encrypted`, `waitingforkey` and media-error events

No licenses, keys, init-data bytes, cookies or credentials are exported.

### 3. Hardware/compositor safety
- application and activity: `hardwareAccelerated=true`
- window: `FLAG_HARDWARE_ACCELERATED`
- WebView: `LAYER_TYPE_NONE`
- one visible fullscreen WebView: `setOffscreenPreRaster(true)`
- never use a software layer for playback
- once Orange creates the player shell, the full opaque native tune cover is removed so the video surface is not completely occluded

### 4. Adaptive UA
A fixed fake Chrome version can cause a server to deliver code intended for a newer browser engine. v0.16 derives compatibility UAs from the real WebView Chromium version and automatically retries alternate profiles. The profile that actually renders frames is persisted.

### 5. Protected media / native DRM
The host records WebView protected-media permission requests and grants only `RESOURCE_PROTECTED_MEDIA_ID` for `*.orange.pl`.

It also checks Android's native Widevine plugin with `MediaDrm.isCryptoSchemeSupported()` and reads non-unique vendor/version/description fields only.

### 6. Recovery ladder
If video stays uninitialized:
1. wake WebView/timers/focus/compositor
2. one non-destructive media retry
3. try remaining UA profiles
4. clear HTTP resource cache while preserving CookieManager session
5. recreate WebView while preserving the same global cookies
6. show a terminal diagnostic

The ladder is bounded; it cannot loop forever.

## Final diagnostic fields

The error screen includes enough information to identify:
- WebView provider/version
- selected UA profile
- hardware acceleration
- native Widevine presence
- protected-media grant/request count
- EME and MSE support
- `readyState`, source state, network state
- encrypted/waiting-for-key counts
- video error code
- recent sanitized console/HTTP errors
