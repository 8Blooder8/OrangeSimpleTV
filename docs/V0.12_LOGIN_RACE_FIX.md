# v0.12 — first-login race fix

## Evidence from real Orange TV Go snapshots

`przed.htm`:
- `[data-testid="login-screen-container"]` exists;
- `input[name="username"]` and `input[name="code"]` exist;
- `[data-testid="button-submit-login"]` is initially disabled.

`podczas.htm`, saved while OrangeSimpleTV still displayed `Czekam na autoryzację`:
- login screen is already gone;
- `[data-testid="home-screen-container"]` exists;
- `[data-testid="navigation-container"]` exists;
- 157 `Channel-ChannelWrapper` nodes are present.

Therefore Orange had already authenticated; the app failed to observe the SPA transition reliably.

## Fix

1. Controlled input values are set through the native `HTMLInputElement.value` setter plus `input/change` events.
2. A disabled submit is never treated as submitted.
3. The next automation tick waits for React to enable the real Orange submit button.
4. After the enabled submit is clicked, `loginSubmitted=true` permanently switches the state machine into probe-only mode; credentials are not resubmitted.
5. `loginState()` uses exact Orange DOM markers, not only page text.
6. A watchdog schedules the next auth probe before each `evaluateJavascript`, so an SPA/navigation race cannot leave the UI stuck forever if a callback is lost.

The original saved Orange HTML files are not committed because saved pages may contain session cookies.
