# v0.15 — non-invasive rendered-frame player

## Evidence

A real Orange TV Go runtime trace showed this sequence:

1. `player-container mode="expanded"` appears.
2. `video#video-player` initially has `readyState=0`, `videoWidth=0`, `videoHeight=0`.
3. Later `playing` fires, the decoded size becomes 768x432 and then 1280x720.
4. `requestVideoFrameCallback` reports actual presented frames.

Therefore neither `mode="expanded"` nor `IconPlayerPause` is sufficient proof that video is visible.

## State machine

`expanded -> VIDEO_WAIT -> render signal -> stable >= 650 ms -> PLAYING -> clean overlay`

A render signal is one of:
- recent `requestVideoFrameCallback`,
- `getVideoPlaybackQuality().totalVideoFrames > 0`,
- recent forward progress of `currentTime`.

Basic readiness also requires:
- `!paused`
- `!ended`
- `readyState >= 2`
- decoded width and height > 0

## Non-invasive clean mode

`enterCleanPlayer()` does not change position, width, height, object-fit, transform, or visibility of the video/container/wrapper. It only makes Orange overlay/control siblings transparent (`opacity:0`) and non-interactive (`pointer-events:none`) while keeping them mounted for React/player lifecycle stability.

Android `onShowCustomView()` no longer calls `finishTune()` immediately. The native loading cover remains until the JS render probe confirms stable playback.

The default WebView video poster is black to avoid the large grey Play placeholder during transient buffering.
