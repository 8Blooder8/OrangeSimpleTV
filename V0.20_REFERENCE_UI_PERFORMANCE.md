# v0.20 — reference UI, eager channel metadata and BlueStacks test mode

## Cel

v0.20 zachowuje działający pipeline Orange z v0.19 i zmienia przede wszystkim warstwę prezentacji, cache i discovery. Zmiany nie ingerują w `video.src`, MediaKeys, DRM ani geometrię chronionego video.

## Referencyjny ekran Kanały

Ekran używa układu około 36/64: po lewej lista kanałów, po prawej duży podgląd i szczegółowa karta programu. Nie ma dolnego paska legendy. Wiersz kanału pokazuje numer, przezroczyste logo, nazwę, bieżący program, zakres godzin i progress. Focus jest renderowany lokalnie przez ciemny gradient i pomarańczowy obrys — przesunięcie focusu nie wykonuje requestu do Orange.

Karta szczegółowa pokazuje logo, numer/nazwę kanału, tytuł programu, godziny, progress, opis jeśli istnieje, bieżący zegar i pozostałe minuty.

## Eager loga zamiast scroll-triggered lazy loading

Zapisany snapshot Orange pokazuje pełną listę kart i programów, ale element `<img>` jest montowany głównie dla elementów znajdujących się w viewport. Dlatego v0.20 nie zakłada, że `img.src` jest dostępne dla całej listy od razu.

Bridge:

1. próbuje odczytać logo z `currentSrc`, `src`, `srcset`, `data-src`, `data-srcset`, `picture/source` i CSS `background-image`,
2. globalny `MutationObserver` zapamiętuje URL po zamontowaniu obrazu przez React,
3. `primeChannelAssets()` wykonuje krótki ukryty sweep brakujących kart i przywraca pozycję strony,
4. discovery bierze pod uwagę wzbogacanie metadanych, nie tylko zmianę liczby kanałów,
5. świeże logo/program/czas są mergowane do już narysowanych wierszy bez pełnego rerenderu.

## Cache logotypów

- L1: RAM,
- L2: dysk,
- bounded executor: 6 workerów,
- cała odkryta lista jest prefetchowana bez ręcznego scrollu,
- jeden URL jest pobierany raz; wszystkie czekające `ImageView` są aktualizowane po zakończeniu,
- preferowane są PNG/WebP/JPEG dla kompatybilności z API 25.

Jeżeli bitmapa rzeczywiście ma wypalony bardzo ciemny mat, wykonywana jest ostrożna normalizacja w tle: tylko przy co najmniej trzech kryjących, ciemnych narożnikach piksele zgodne z kolorem tła stają się przezroczyste. Bitmap już przezroczystych nie ruszamy.

## EPG i progress

Model kanału przechowuje `programStartMs`, `programEndMs`, `programProgressHint`, `programDescription` i timestamp aktualizacji. Bridge próbuje odczytać dane bezpośrednio z kafla oraz, gdy jest to możliwe, skojarzyć bieżący tytuł z widokami programu udostępniającymi progress/godzinę.

Nie zakładamy, że Orange eksponuje opis i pełne godziny dla każdego kanału. Progress oraz `X min do końca` są aktualizowane lokalnie co 30 s. Cache kanałów działa w modelu stale-while-revalidate.

## Overlay nad działającym video

`BACK` podczas oglądania nie wykonuje `WebView.onPause()`, nie zmienia visibility playera, nie przełącza expanded → background, nie resize'uje video/WebView i nie wykonuje reloadu. Na wierzchu pojawia się tylko lewy panel kanałów. Ponowne `BACK` usuwa panel. `OK` na innym kanale używa istniejącego warm switch.

## BlueStacks

Detekcja emulatora obejmuje standardowe generic/goldfish/ranchu oraz typowe identyfikatory BlueStacks/virtualbox. W emulatorze Widevine nie jest wymagane do testu UX: zamiast streamu renderowany jest pełnoekranowy placeholder, a overlay, program info, numery i CH+/CH− pozostają aktywne.

Jeżeli prawdziwe EPG nie dostarcza wszystkich pól, wyłącznie w emulatorze brakujące godziny/opis mogą być syntetyczne w celu oceny układu. Takie dane nie są zapisywane jako prawdziwy cache EPG.

## Klawiatura

- Arrow Up/Down → focus,
- Enter / DPAD_CENTER → OK,
- Esc / Backspace / Android BACK → BACK,
- Page Down / KEYCODE_CHANNEL_UP → następny kanał w dół,
- Page Up / KEYCODE_CHANNEL_DOWN → poprzedni kanał w górę,
- Space / MEDIA_PLAY_PAUSE → Play/Pause,
- cyfry → szybki wybór numeru,
- Home/End → pierwszy/ostatni kanał.

## Granice optymalizacji

Warm switch z v0.18/v0.19 pozostaje zachowany. Pełne probe EME/MediaDrm uruchamiają się tylko w ścieżce diagnostycznej, a nie podczas każdej zmiany kanału. Playback/DRM pozostaje własnością oficjalnego playera Orange.
