# v0.23 — lokalne logotypy, stabilne numery i close-before-switch

v0.23 jest poprawką pod fizyczny DIW377. Nie zmienia loginu Orange, Widevine, EME/MSE, `video.src`, MediaKeys ani mechanizmu pierwszej renderowanej klatki.

## Lokalne logotypy

Do APK dołączono katalog `app/src/main/assets/channel_logos/` przygotowany z przekazanego eksportu Orange TV Go:

- 155/155 kanałów ma lokalny plik PNG,
- `catalog.json` przechowuje canonical numer, nazwę i nazwę pliku,
- normalny frontend nie pobiera logotypów z sieci,
- lista, karta EPG i overlay `OK` korzystają z tego samego lokalnego assetu,
- brak dopasowania nie jest maskowany losowym fallbackiem internetowym; trafia do diagnostyki.

To usuwa zależność logo od lazy DOM/scrolla Orange i skraca hot-path listy.

## Stabilny numer kanału

v0.22 miał dwa źródła niestabilności: bridge numerował kanały przez pozycję bieżącego discovery, a native `mergeVisibleChannelMetadata()` scalał świeże dane z istniejącą listą po indeksie. Jeżeli React montował kafelki w innej kolejności, metadata mogły trafić do innego kanału, a numer był pochodną chwilowej tablicy.

v0.23 rozdziela identity od pozycji discovery:

- canonical numer pochodzi z lokalnego katalogu 155 kanałów,
- dopasowanie podstawowe odbywa się po znormalizowanej nazwie kanału,
- nieznany przyszły kanał dostaje utrwalony fallback w SharedPreferences,
- metadata refresh scala po identity/nazwie, nigdy po indeksie,
- lista jest sortowana po stabilnym `Channel.number`.

W dostarczonym katalogu `Polsat Rodzina` ma canonical numer 83 i pozostaje 83 niezależnie od kolejności discovery.

## Wybór aktualnie oglądanego kanału

Gdy guide jest nałożony na działający player i użytkownik wybierze ponownie ten sam kanał, aplikacja wyłącznie ukrywa guide. Nie rozpoczyna tune, nie pokazuje loadingu i nie restartuje playera.

## Close-before-switch

Usunięto model `A expanded -> A minimized/background -> aktywuj B`.

v0.23 używa `A expanded -> szary loading cover -> zamknij A przez własny handler Orange -> aktywuj B -> potwierdź identity -> expanded -> real frame -> ukryte Orange UI -> commit`.

`prepareFastChannelSwitch()` znajduje rzeczywisty przycisk `ClosePlayerButtonWrapper` i w pierwszej kolejności wywołuje jego handler React. Nie usuwa `<video>`, nie modyfikuje MediaKeys i nie zmienia źródła media. Native state machine po żądaniu close czeka na zniknięcie `player-container`. Nie istnieje już `TAP_MINIMIZE` ani timeout, który uznawał stary background player za nowy kanał.

## Rollback

Każdy switch zachowuje poprzedni stabilny kanał do momentu `SWITCH_COMMIT`. Jeżeli close starego playera nie nastąpił, failure zdejmuje cover i pozostawia poprzedni player. Jeżeli stary player został zamknięty, failure wykonuje jedną ograniczoną próbę ponownego tune poprzedniego kanału. `currentChannelIndex` jest aktualizowany dopiero w `finishTune()`.

## Orange top bar i player chrome

Bridge instaluje trwałe reguły ukrywające webowy UI Orange bez ingerencji w video: hamburger/Start/search/settings/top chrome, base overlay playera, Play/Pause, timeline/LiveSeekbar, program/info/settings/expand controls, tooltipy i gradienty controls. `MutationObserver` ponawia suppression po remountach Reacta.

Native szary `Ładowanie…` pozostaje nad WebView aż jednocześnie są spełnione: identity docelowego kanału, player `expanded`, potwierdzona renderowana klatka, ukryty player chrome i sukces clean-player gate.

## Live edge

Po potwierdzeniu playbacku bridge odczytuje `video.currentTime`, ostatnie `video.seekable.end(...)`, `liveOffsetSeconds` oraz stan oficjalnego przycisku Orange `IconPlayerLive` (`Na żywo`). Jeżeli player jest wyraźnie za live edge (próg 15 s) i Orange udostępnia aktywny przycisk `Na żywo`, v0.23 używa jego handlera. Nie wykonuje bezpośredniego `video.currentTime = ...`.

## Diagnostyka DIW377

Raporty są zapisywane do `/storage/emulated/0/Android/data/pl.blazej.orangesimpletv/files/ostv-diagnostics/`.

Najważniejsze pliki:

- `ostv-guide-latest.json` — stabilny numer, channelId, EPG source, local logo mapping i listy unresolved,
- `ostv-switch-latest.json` — ostatni handoff z chronologicznym event trace,
- `ostv-switch-last-failure.json` — ostatni nieudany handoff zachowany po późniejszym rollbacku,
- `ostv-diagnostic-session-<id>.json` — terminalna diagnostyka tune.

Event trace obejmuje m.in. `SWITCH_REQUEST`, `OLD_PLAYER_CLOSE_REQUEST`, `OLD_PLAYER_CLOSED`, `TARGET_TILE_ACTIVATE`, `TARGET_PLAYER_CREATED`, `TARGET_IDENTITY_CONFIRMED`, `TARGET_EXPANDED`, `TARGET_FRAME_RENDERED`, `LIVE_EDGE_CHECK`, `LIVE_EDGE_CORRECTED`, `PLAYER_CHROME_HIDDEN`, `SWITCH_COMMIT` i rollback.

Raporty nie zapisują cookies, Authorization ani danych licencji Widevine.
