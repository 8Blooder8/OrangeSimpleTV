# v0.25 — decoder fixes

## Root causes

1. **Wrong local logo / duplicate number**: v0.24 used the embedded logo catalogue number both as lineup number and as a fallback logo key. A channel absent from the supplied logo ZIP could therefore inherit the asset belonging to another channel at the same numeric slot. The lineup number fallback was also persisted without collision awareness.
2. **Audio already playing but loading never ends**: on DIW377 protected video can advance `currentTime` while JS still reports `videoWidth/videoHeight=0`. The v0.24 render gate therefore rejected real playback until timeout.
3. **Random programme times**: the hover sweep primed four cards at once. Orange mounts `Channel-ProgramTime` as transient hover state, so parallel hover batches were nondeterministic.

## v0.25 model

- Local logo mapping: normalized channel identity/name only. No number fallback.
- Lineup numbering: Orange discovery order is the preferred number; the result is persisted per channelId/name under `channel_no_v4_*` and assigned through a used-number set so one pass cannot contain duplicates.
- Guide cache key: `channel_cache_v4` to discard bad v0.24 numbering.
- Protected playback proof: expanded player + readyState >= 2 + media source + advancing currentTime can prove playback when dimensions are hidden by an OEM protected surface. Normal RVFC/playback-quality/dimensions signals still remain preferred where available.
- Player mode: near-fullscreen geometry overrides a stale `mode=background` attribute.
- Live-edge correction is post-commit and does not keep the loading cover visible.
- EPG tile sweep is sequential: one hover at a time, then capture `Channel-ProgramTime`, leave, next tile. Fresh channel discovery forces a new sweep generation.

No direct `video.src`, MediaKeys, MediaSource or Widevine manipulation was added.
