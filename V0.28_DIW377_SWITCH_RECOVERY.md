# v0.28 — DIW377 switch recovery

## Evidence from v0.27 runtime

The latest failure was a switch from `Cartoon Network HD` to `TeenNick HD`. The exported failure file was internally inconsistent: its top-level fields described session 5 while `events` and `stateTransitions` already belonged to rollback session 6. This proved that `writeSwitchDiagnostic()` read mutable global trace fields only after asynchronous `uiDiagnostics()` returned.

A later clean tune of `TeenNick HD` succeeded with `TARGET_PLAYER_CREATED`, `TARGET_IDENTITY_CONFIRMED`, `TARGET_FRAME_RENDERED` and `SWITCH_COMMIT`. Therefore the target channel/player/DRM path itself works when started from a clean channel-list state. The remaining failure is specific to the warm post-close activation path.

## Changes

1. 140 ms post-close DOM settle after confirmed old-player unmount.
2. Warm target activation deadline: 4 s.
3. One recovery only: reload official `/channels`, reset tile activation counters, retry the same target. No rollback before this recovery.
4. User request wins over a queued automatic rollback.
5. Immutable switch diagnostic snapshot before rollback; per-session files plus explicit failure code/reason.

The app still does not replace Orange media URLs, MediaKeys, MSE or Widevine handling.
