# v0.21 — EPG enrichment przed gotowym guide

## Przyczyna błędu v0.20

Analiza rzeczywistego zapisanego DOM Orange pokazała dwie różne warstwy danych:

- `Channel-ChannelWrapper` udostępnia od razu nazwę kanału i `Channel-ProgramName`,
- dokładny start/koniec/opis nie są gwarantowane w samym kafelku kanału.

W jednym zapisanym snapshotcie było 157 kart kanałów, ale tylko 138 elementów `PromotedProgram-Container`. Dopasowanie wyłącznie po tytule programu nie może więc być kompletnym źródłem EPG; dodatkowo tytuły mogą różnić się suffixem odcinka albo być niejednoznaczne (`News`).

v0.20 kończył discovery, gdy lista kanałów była stabilna i około 75% logotypów miało URL, albo po krótkim czasie. Wynik `channelMetadataScore()` nie był warunkiem kompletności EPG. Po kliknięciu kanału Orange tworzył player z bogatszymi danymi i późniejszy refresh przypadkowo uzupełniał godziny — stąd obserwowane „godziny pojawiają się dopiero po kliknięciu”.

## Model v0.21

`discoverChannels()` zwraca teraz osobny status EPG:

- `started`,
- `reactDone`,
- `resourcesDone`,
- `done`,
- `complete`,
- `programs`,
- `schedules`,
- `unresolved`,
- liczby trafień z React/store/resource.

`done` = wszystkie ograniczone skanery/retry zakończyły pracę.

`complete` = każdy wykryty kanał mający aktualny program ma prawidłowy `startMs` i `endMs`.

Native guide uznaje świeże dane za gotowe dopiero przy `done && complete` oraz pełnym harvest URL-i logo. Całość pozostaje ograniczona `DISCOVERY_TIMEOUT_MS`; nie ma nieskończonego oczekiwania.

## Źródła enrichmentu

### 1. Kafelek DOM

Jeżeli Orange umieści zakres czasu/progress bezpośrednio w kafelku, jest używany bez dalszej pracy.

### 2. React per channel

Dla każdego `Channel-ChannelWrapper` bridge sprawdza expando React:

- `__reactProps$...`,
- `__reactFiber$...`,
- `__reactInternalInstance$...`.

Następnie przechodzi ograniczoną liczbę rodziców Fiber i analizuje `memoizedProps`, `pendingProps`, `memoizedState`. Obsługiwane są typowe warianty nazw pól `startTime/startDateTime/broadcastStart/...`, `endTime/...`, `description/synopsis/...`.

### 3. Globalny React store/state

Hostowy DIV kafelka często ma tylko `children/className`, podczas gdy nadrzędny komponent zachowuje tablicę modeli kanałów/programów. v0.21 wykonuje jeden szerszy, ograniczony skan store/state nad ekranem kanałów i odkłada tylko wykryte metadane programu do cache.

### 4. Program DOM index

Pozostaje fallback na `PromotedProgram-Container`, ale matching jest ostrożniejszy:

- normalizacja znaków,
- usuwanie suffixów `odc./sezon/część`,
- prefix/fuzzy score,
- krótkie tytuły muszą mieć jednoznaczny exact match.

### 5. Same-origin JSON resource fallback

Po React scan bridge może ponownie odczytać maksymalnie kilka już zaobserwowanych URL-i, ale tylko gdy nazwa zasobu jawnie zawiera `epg`, `program`, `programme`, `guide` albo `schedule`.

Nie są replayowane:

- `/live/channel/...`,
- playback/stream endpoints,
- MPD/HLS,
- DRM/Widevine/licence/certificate.

Odpowiedź ma limit rozmiaru; surowy JSON nie jest utrwalany. Do cache trafiają wyłącznie pola EPG.

## Delayed state

Po pierwszym przebiegu v0.21 wykonuje kilka tanich retry tylko dla kanałów bez zakresu czasu. Jest to potrzebne, gdy React zamontował kafelki wcześniej niż otrzymał pełny state EPG. Retry są chunkowane i mają twardy deadline około 5,2 s wewnątrz 6 s deadline native discovery.

## Cache

`channel_cache_v2` unieważnia niepełny cache v0.20.

Jeżeli poprzednia lista jest już w cache:

1. UI pokazuje ją natychmiast,
2. świeże EPG ładuje się w tle,
3. update podmienia tylko pewniejsze dane,
4. niepełny refresh nie zeruje wcześniej znanych godzin.

## Playback

Zmiany dotyczą guide/metadata. Nie zmieniono logiki:

- login,
- hover → prawdziwy Play,
- warm channel switch,
- MediaDrm/EME,
- `video.src`/MediaKeys,
- first rendered frame gate.
